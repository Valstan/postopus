### [2026-04-05] - Рефакторинг логики парсинга-фильтрации-постинга тематических заданий

**Что изменено:**
- **Исправлен критический баг P0:** `karavan.py` - `random.choice(msg_list)` вызывал `IndexError` при пустом списке
- **Исправлен баг P1:** `posting_post.py` - убрана критическая зависимость от `session["setka_regim_repost"]` для тем `sosed`, `repost_oleny`, `karavan`. Теперь постинг работает даже если режим репоста выключен (fallback на обычную публикацию)
- **Исправлен баг P3:** `repost_oleny.py` - добавлена валидация что `msg_list` не пуст перед постингом
- **Добавлена обработка ошибок VK API** во все контроллеры: `karavan.py`, `sosed.py`, `repost_oleny.py`, `repost_me.py`, `repost_reklama.py`, `repost_kultpodved.py`, `oblast_novost.py`, `post_to_telega.py`
- **Добавлены 13 новых unit-тестов:**
  - `tests/test_karavan.py` - 4 теста (пустой список, уже опубликовано, успешный постинг, ошибка VK API)
  - `tests/test_sosed.py` - 4 теста (нет постов, уже опубликовано, успешный постинг, ошибка VK API)
  - `tests/test_repost_oleny.py` - 5 тестов (пустой список, уже опубликовано, успешный постинг, ошибка VK API, исключение исходной группы)

**Затронутые файлы:**
- `bin/control/karavan.py` - добавлена валидация msg_list, обработка ошибок, try-except
- `bin/control/sosed.py` - добавлена обработка ошибок, try-except
- `bin/control/repost_oleny.py` - исправлена логика постинга (убран дублирующий постинг N раз), добавлена валидация
- `bin/control/repost_me.py` - добавлена обработка ошибок
- `bin/control/repost_reklama.py` - добавлена обработка ошибок, валидация пустого списка
- `bin/control/repost_kultpodved.py` - добавлена обработка ошибок, валидация, возврат `[]` вместо None
- `bin/control/oblast_novost.py` - добавлена обработка ошибок
- `bin/control/post_to_telega.py` - добавлена обработка ошибок
- `bin/rw/posting_post.py` - **КРИТИЧЕСКОЕ ИЗМЕНЕНИЕ:** убрана зависимость от `setka_regim_repost`, добавлен fallback логику
- `tests/test_karavan.py` - новый файл
- `tests/test_sosed.py` - новый файл
- `tests/test_repost_oleny.py` - новый файл

**Причина изменения:**
- **Karavan:** падал с `IndexError` при пустом `msg_list` → полная остановка постинга
- **Sosed/Karavan/Repost_oleny:** не публиковали посты если `setka_regim_repost == False/None` → тематики не доходят до финиша
- **Repost_oleny:** публиковал **каждый** пост N раз (по одному разу в каждую группу) → дублирование контента
- **Все контроллеры:** отсутствие обработки ошибок VK API → непредсказуемое поведение при сбоях

**Влияние на другие модули:**
- `posting_post.py` - изменение затрагивает все темы которые используют `setka_regim_repost`
- Все контроллеры теперь имеют единообразную обработку ошибок
- Добавленные тесты обеспечивают регрессионную защиту

**Обратная совместимость:**
- ✅ **ДА** - все изменения обратно совместимы
- Старые функции сохранили сигнатуры
- `setka_regim_repost` продолжает работать если включен, но теперь есть fallback
- Никаких breaking changes

**Тесты:**
- ✅ Все 47 тестов проходят (34 существующих + 13 новых)
- Покрытие: karavan (4 теста), sosed (4 теста), repost_oleny (5 тестов)

### [2026-04-02] - Исправлен парсер: сохраняем медиа-вложения в дайджестах

**Что изменено:**
- В `bin/control/parser.py` убрано удаление ключа `attachments` для постов без поля `views`.

**Затронутые файлы:**

**Влияние на другие модули:**

**Обратная совместимость:**
- Изменение низкоопасное: поведение осталось прежним для темы `reklama`, для других тем вложения теперь сохраняются, что устраняет потерю медиа.

### [2026-04-01] - Разделение тестов: unit-тесты vs интеграционные

**Что изменено:**
- Переименован `test_start_paket.py` → `test_start_paket_integration.py` (требует MongoDB и всех 15 регионов).
- Создан новый `test_start_paket.py` с unit-тестами для CLI парсинга (без MongoDB).
- Добавлены новые unit-тесты в папку `tests/`:
  - `tests/test_env_loader.py` — 11 тестов конфигурации и TEST_POLYGON
  - `tests/test_posting_post.py` — 5 тестов редиректа в тестовый полигон
  - `tests/test_start_cli.py` — 9 тестов парсинга CLI аргументов (в т.ч. `--test`)
  - Обновлены существующие `tests/test_driver_tables_no_mongo.py` и `tests/test_session_parser.py`
- Создана конфигурация `pytest.ini` для управления тестами.
- Создана документация `TESTING.md` с описанием всех тестов.

**Затронутые файлы:**
- `test_start_paket.py` (переименован → интеграционный)
- `test_start_paket_integration.py` (новое имя)
- `tests/test_env_loader.py` (новый)
- `tests/test_posting_post.py` (новый)
- `tests/test_start_cli.py` (новый)
- `pytest.ini` (новый)
- `TESTING.md` (новый)

**Причина изменения:**
- Интеграционный тест `test_start_paket.py` потребляет токены VK и требует MongoDB для всех 15 регионов (15+ минут).
- Это замораживает CI/CD и опасно для автоматизации.
- Решение: unit-тесты (28 тестов) для CI/CD, интеграционный тест отделён.

**Как использовать:**
- CI/CD: `pytest tests/ -q` (10–15 сек, безопасно, нет токенов) ✅
- Локально (полный): `python test_start_paket_integration.py` (только при необходимости)
- Локально (быстро): `pytest tests/ -v` (проверка логики)
- Тестовый режим: `python start.py mi_novost --test` (публикует в полигон вместо рабочей группы)

**Результат:**
- GitHub Actions теперь быстро проходит CI без потребления токенов ✅
- Разработчик может локально тестировать логику без MongoDB ✅
- Интеграционные тесты доступны при необходимости (отдельный запуск) ✅
- Все 28 unit-тестов прошли локально ✅

### [2026-04-01] - Тестовый режим публикаций через флаг --test и переменную окружения

**Что изменено:**
- В `env_loader.py` добавлена переменная `TEST_POLYGON_GROUP_ID` (числовой ID сообщества: -137760500) и флаг `TEST_POLYGON_MODE`.
- В `bin/rw/posting_post.py` добавлена явная логирующая запись (`logger.info`) при перенаправлении публикации в тестовый полигон.
- В `start.py` реализована поддержка CLI-флага `--test`, который включает `session['post_to_test_polygon'] = True` на время запуска (не требует изменения `.env`).

**Затронутые файлы:**
- `env_loader.py` (добавлен TEST_POLYGON config)
- `bin/rw/posting_post.py` (логирование перенаправления в тестовый полигон)
- `start.py` (CLI: поддержка `--test`)

**Причина изменения:**
- Упростить безопасное тестирование публикаций: во время разработки или CI можно запускать `start <session> --test` и все посты попадут в тестовый полигон вместо рабочих сообществ.

**Как использовать:**
- Быстрый запуск в тестовом режиме: `python start.py mi_novost --test` — публикации будут направлены в сообщество с ID -137760500.
- Альтернатива: установить `TEST_POLYGON_MODE=true` в `.env` для постоянного тестового режима.

**Влияние на другие модули:**
- Низкорискованное: поведение меняется только при активном флаге `--test` или установленной переменной окружения. По умолчанию поведение прежнее.

**Обратная совместимость:**
- Сохранена: без `--test` и без `TEST_POLYGON_MODE` всё работает как раньше.
