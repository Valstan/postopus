### [2026-04-01] - Устранение проблем с тематиками и поддержка коротких кодов региона

**Что изменено:**
- `bin/rw/get_session.py` — добавлена поддержка коротких кодов региона (например, `mi`) с автоматическим сопоставлением на полное имя региона; дополнительно обеспечена загрузка/инициализация таблиц `novost` для тематик, отличных от `novost`, и `bezfoto`/`all_bezfoto` для `reklama`.
- `bin/control/parser.py` — защищённый доступ к заголовкам (`zagolovok`) с корректным fallback на `zagolovki` или пустую строку, чтобы отсутствие ключа в конфиге не приводило к KeyError.
- `.env.example` — добавлен пример файла окружения (без секретов).

**Затронутые файлы:**
- `bin/rw/get_session.py` — поддержка коротких кодов и загрузки рабочих таблиц
- `bin/control/parser.py` — безопасные lookup'и заголовков
- `.env.example` — пример переменных окружения (без реальных токенов)
- `DEV_HISTORY.md` — эта запись

**Причина изменения:**
- Ранее некоторые темы (например, `kultura`, `sport`, `reklama` и др.) падали с `KeyError` или не могли определить целевую группу при передаче короткого кода региона в аргументе (`mi_novost`). Причина — отсутствие ожидаемых таблиц в `session['work']` и несовпадающие форматы имени региона.

**Что сделано:**
- Автоматическое сопоставление коротких кодов региона → полное имя региона, чтобы поиск `post_group_vk` в `all_my_groups` работал корректно.
- Гарантированная загрузка/инициализация `session['work']['novost']` для тем, использующих общую историю публикаций, и `bezfoto`/`all_bezfoto` для рекламы.
- Защищённый доступ к строкам-заголовкам (`zagolovok`) с fallback, чтобы отсутствие ключей в конфиге не приводило к аварийному завершению.

**Влияние на другие модули:**
- Улучшение устойчивости: модули сортировки (`sort_po_foto`, `sort_po_video`), `post_bezfoto` и сам `parser` больше не падают при отсутствии предварительно загруженных таблиц.
- Поведение при использовании полноформатных имён регионов не изменилось.

**Обратная совместимость:**
- Сохранена: старый способ передачи аргументов (`"Малмыж - Инфо_kultura"`) и поведение сохраняются.

**Проверки:**
- Запущены unit-тесты: `pytest` → 27 passed.
- Прогоны в тестовом режиме: `start.py mi_novost --test`, `mi_reklama`, `mi_addons`, `mi_kultura` — темы отработали без KeyError; определение `post_group_vk` и редирект в TEST_POLYGON при `--test` подтверждены.

**Рекомендуется:**
- Оставить `.env.example` и НЕ коммитить `.env` с реальными токенами.
- При добавлении новых регионов поддерживать как полное имя (для `all_my_groups`), так и короткий код в `region_to_collection` при необходимости.

### [2026-04-01] - Разделение тестов: unit-тесты vs интеграционные

**Что изменено:**
- Переименован `test_start_paket.py` → `test_start_paket_integration.py` (требует MongoDB и всех 15 регионов).
- Создан новый `test_start_paket.py` с unit-тестами для CLI парсинга (без MongoDB).
- Добавлены новые unit-тесты в папку `tests/`:
  - `tests/test_env_loader.py` — 11 тестов конфигурации и TEST_POLYGON
  - `tests/test_posting_post.py` — 5 тестов редиректа в тестовый полигон
  - `tests/test_start_cli.py` — 9 тестов парсинга CLI аргументов (в т.ч. `--test`)
  - Обновлены существующие `tests/test_driver_tables_no_mongo.py` и `tests/test_session_parser.py`
- Создана конфигурация `pytest.ini` для управления тестами.
- Создана документация `TESTING.md` с описанием всех тестов.

**Затронутые файлы:**
- `test_start_paket.py` (переименован → интеграционный)
- `test_start_paket_integration.py` (новое имя)
- `tests/test_env_loader.py` (новый)
- `tests/test_posting_post.py` (новый)
- `tests/test_start_cli.py` (новый)
- `pytest.ini` (новый)
- `TESTING.md` (новый)

**Причина изменения:**
- Интеграционный тест `test_start_paket.py` потребляет токены VK и требует MongoDB для всех 15 регионов (15+ минут).
- Это замораживает CI/CD и опасно для автоматизации.
- Решение: unit-тесты (28 тестов) для CI/CD, интеграционный тест отделён.

**Как использовать:**
- CI/CD: `pytest tests/ -q` (10–15 сек, безопасно, нет токенов) ✅
- Локально (полный): `python test_start_paket_integration.py` (только при необходимости)
- Локально (быстро): `pytest tests/ -v` (проверка логики)
- Тестовый режим: `python start.py mi_novost --test` (публикует в полигон вместо рабочей группы)

**Результат:**
- GitHub Actions теперь быстро проходит CI без потребления токенов ✅
- Разработчик может локально тестировать логику без MongoDB ✅
- Интеграционные тесты доступны при необходимости (отдельный запуск) ✅
- Все 28 unit-тестов прошли локально ✅

### [2026-04-01] - Тестовый режим публикаций через флаг --test и переменную окружения

**Что изменено:**
- В `env_loader.py` добавлена переменная `TEST_POLYGON_GROUP_ID` (числовой ID сообщества: -137760500) и флаг `TEST_POLYGON_MODE`.
- В `bin/rw/posting_post.py` добавлена явная логирующая запись (`logger.info`) при перенаправлении публикации в тестовый полигон.
- В `start.py` реализована поддержка CLI-флага `--test`, который включает `session['post_to_test_polygon'] = True` на время запуска (не требует изменения `.env`).

**Затронутые файлы:**
- `env_loader.py` (добавлен TEST_POLYGON config)
- `bin/rw/posting_post.py` (логирование перенаправления в тестовый полигон)
- `start.py` (CLI: поддержка `--test`)

**Причина изменения:**
- Упростить безопасное тестирование публикаций: во время разработки или CI можно запускать `start <session> --test` и все посты попадут в тестовый полигон вместо рабочих сообществ.

**Как использовать:**
- Быстрый запуск в тестовом режиме: `python start.py mi_novost --test` — публикации будут направлены в сообщество с ID -137760500.
- Альтернатива: установить `TEST_POLYGON_MODE=true` в `.env` для постоянного тестового режима.

**Влияние на другие модули:**
- Низкорискованное: поведение меняется только при активном флаге `--test` или установленной переменной окружения. По умолчанию поведение прежнее.

**Обратная совместимость:**
- Сохранена: без `--test` и без `TEST_POLYGON_MODE` всё работает как раньше.

### [2025-03-26] - Автоматический сбор статистики постинга и публикация в Тестовый полигон

- Новый модуль `publish_stats.py` использует существующие функции `post_msg()` и `get_session_vk_api()`
- Обратная совместимость сохранена: функция `start()` по-прежнему поддерживает параметр `stat_mode`

**Обратная совместимость:**
- Полностью сохранена: старый код продолжает работать
- Изменено только поведение `start_paket.py` в части сбора и вывода статистики
- Функция `start()` и контроллеры остаются совместимыми
